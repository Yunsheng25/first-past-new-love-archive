# 全站素材预加载页设计

## 目标

访客进入网站时先看到加载页。网站代码以及 `assets` 下全部图片、音频和视频成功进入浏览器缓存后，加载页才淡出并展示当前路由。进入网站后，图片详情、复盘案例和视频不再等待首次网络请求。

## 加载流程

1. HTML 首屏直接渲染独立加载界面，避免 JavaScript 下载与执行前出现纯黑空白。
2. 构建脚本生成稳定的素材清单，记录每个公开素材的路径与字节数。
3. 浏览器以有限并发逐项请求素材，避免同时发起两百多个请求。
4. 加载页显示真实的文件完成进度、累计字节进度、当前加载阶段和失败重试状态。
5. 单项失败自动重试；仍失败时提供“重新加载”按钮，不进入内容页。
6. 全部成功后挂载现有路由，再以短暂淡出动画移除加载层。

## 缓存与重复访问

资源请求使用浏览器 HTTP 缓存。再次访问时仍执行完整性检查，但已缓存的素材应快速命中本地缓存。加载器不把 510MB 素材同时保存在 JavaScript 内存中，只消费响应数据并让浏览器管理磁盘缓存。

## 交互与视觉

加载页沿用网站的黑金电影档案风格，主体为一条斜向缓慢穿过画面的影像长卷，包含项目标题、细线进度轨道、百分比、已加载容量和当前素材阶段。

长卷保持单层、清晰且不拥挤。尚未加载的卡片呈低饱和暗片；素材成功进入缓存后，对应卡片逐张显影为清晰图片并保留点亮状态。鼠标使用现有圆环语言，移动时形成一圈暗房显影波纹；波纹靠近卡片时，卡片短暂抬起、增亮并增强清晰度。鼠标移动还会给整条长卷带来幅度很小的纵深偏移。

动画尊重减少动态效果设置。加载期间不显示正文或可点击入口。

## 验证

- 素材清单覆盖所有公开素材且路径不存在遗漏。
- 未完成时不挂载网站内容。
- 全部成功后只进入一次。
- 单项失败按限制次数重试，并在最终失败时提供明确恢复操作。
- 加载器销毁后不留下计时器、监听器或重复请求。
- 完整测试套件通过，并在本地模拟慢速与失败请求。
