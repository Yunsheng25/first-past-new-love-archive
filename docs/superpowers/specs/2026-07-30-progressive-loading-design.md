# 《初恋 · 旧爱 · 新欢》渐进式加载设计

## 目标

在继续使用现有 GitHub Pages 网址的前提下，显著缩短首次打开和页面切换的等待时间，同时保持现有视觉、交互、原片画质、案例顺序和内容完整性。

## 已确认的根因

- 首页在显示前阻塞下载 11.8 MiB 的背景视频；当前实测约需 25 秒。
- BGM 为 6.3 MiB；当前实测约需 18 秒。
- 全站清单共 204 个资源、486.6 MiB。
- 首屏显示后，程序立即以两路并发下载其余全部素材。这会长期占用连接，使随后点击的复盘图片、提示词图片和影片请求排队。
- 因此，单纯更换加载动画或更换域名不能解决根因。

## 加载原则

### 1. 网站外壳优先

加载动画只等待网站运行所必需的 HTML、CSS 和 JavaScript，不等待任何大视频、BGM 或案例媒体。外壳可用后立即进入首页。

保留现有加载动画和退场效果，但网络资源不再控制动画是否结束。加载失败时，页面仍应能够进入并显示媒体自己的重试状态。

### 2. 首页背景渐进增强

首页先显示现有暗色背景、标题和观看按钮。背景视频使用 `preload="metadata"` 或等效的非阻塞方式加载；首个可播放画面准备好后再淡入。

背景视频未完成加载时，标题、鼠标动效、粒子和导航保持可用，不出现黑屏等待。

### 3. 音频按意图加载

BGM 默认关闭时不下载音频正文。只有用户明确开启音乐时才开始请求 BGM；进入完整影片时继续遵守现有淡出规则。

### 4. 完整影片按点击加载

首页不预下载 62.3 MiB 完整影片。用户点击“观看完整成片”后，播放器立即出现并使用浏览器原生流式加载、范围请求和进度拖动。

保留退出影片、全屏、播放失败重试和影片结束后的跳转。

### 5. 复盘按阅读位置加载

进入复盘时先下载结构化文本。当前页媒体优先加载；上一页和下一页只做低优先级预取。更远页面保持懒加载。

媒体未到达时显示与版面尺寸一致的深色占位，避免文章跳动；到达后平滑显现。批注、图片和视频的原有组合与顺序不改变。

### 6. 提示词按可见窗口加载

提示词隧道继续使用现有可见窗口机制，只请求当前视野及临近卡片。思维导图节点的图片在展开或接近可见区时加载。

详情弹窗优先请求该案例的全部图片，首尾帧仍按原有上下顺序展示。错误案例分支和案例顺序不改变。

## 数据流

1. 浏览器读取 HTML、CSS 和模块入口。
2. 加载动画短暂展示，应用外壳准备好后立即退场。
3. 当前路由挂载自身的资源调度器。
4. 调度器只请求“当前可见”“即将可见”“用户明确触发”的资源。
5. 路由切换时取消尚未开始的低优先级预取，优先服务新页面。
6. 浏览器缓存已完成的资源；再次访问不重复下载。

## 不在本次范围

- 不迁移托管平台。
- 不改变现有公开网址。
- 不压缩或重编码完整影片。
- 不重排复盘案例、批注媒体或提示词案例。
- 不改变已确认的视觉风格和鼠标交互。

## 验收标准

- 首页显示不再等待背景视频完整下载。
- 首次进入首页时，不请求完整影片、BGM、全部复盘媒体或全部提示词图片。
- 首页显示后，不再启动全站 486.6 MiB 后台预载。
- 点击完整影片后，播放器立即可见，加载期间可退出；加载后可播放、拖动和全屏。
- 复盘当前页媒体优先于远端页面媒体；翻到相邻页时图片已有缓存或显示稳定占位。
- 提示词隧道和导图只加载可见窗口及临近图片。
- 媒体失败不会阻塞整个网站，并提供现有重试或可理解的失败状态。
- 所有现有自动化测试继续通过；新增测试证明大资源不会在首屏被请求。

## 回退策略

改动在独立分支完成。发布前使用本地限速验证首页、影片、复盘和提示词四条路径；任何主要交互退化时不推送生产分支，现有 GitHub Pages 保持不变。
