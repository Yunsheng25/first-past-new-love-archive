# 《初恋旧爱新欢》项目网站设计说明

日期：2026-07-18  
状态：待用户书面审阅

## 1. 项目目标

网站用于完整呈现《初恋旧爱新欢》的成片、创作经历、制作图片、生成提示词和复盘手记。

网站首先让访客观看作品，再让访客自行选择深入方向：阅读复盘，或查看图片与提示词。目标受众以希望完整了解作品与故事的人、对 AI 视频制作过程感兴趣的人为主，同时兼顾潜在合作方和面试官。

成功标准：

- 访客打开网站后能立即进入作品氛围并观看成片。
- 成片结束后，访客能清楚选择“复盘手记”或“提示词和图片”。
- 两万字复盘不以无限长页面呈现，而是能够按目录和阅读页逐步浏览。
- 137 张不同图片及相关提示词全部保留，并能够搜索、筛选和逐案例查看。
- 手机和电脑均可正常观看、选择和阅读。

## 2. 不做的内容

- 不把网站设计成传统多栏目作品集。
- 不在影片观看前提供复杂的栏目导航。
- 不把首页做成持续向下滚动的项目故事页。
- 不把两万字复盘堆在一个长页面中。
- 不把原始 Obsidian Canvas 白板直接作为主要浏览界面。
- 不删减图片或仅展示精选案例。

## 3. 核心体验流程

```text
全屏片头
  ↓ 点击“观看完整成片”
全屏播放完整成片
  ↓ 播放结束
片后选择
  ├── 复盘手记
  └── 提示词和图片
```

访客可以在任一深入页面返回片后选择，也可以重新观看影片。

## 4. 全屏片头与成片播放

### 4.1 全屏片头

片头以真实成片作为整个屏幕的动态背景。背景使用整部成片静音、4 倍速、循环播放，不另用静态封面图替代。

视频初始透明度设为约 58%，根据不同镜头的明暗在 55%–65% 之间微调。文字必须始终清楚，但不能将视频压暗到看不清内容。

中央文字设计、顶栏比例、暖灰金色、宋体主标题、中英文层级和细小红色装饰点，以以下参考图为正式视觉基准：

- `design-references/homepage-approved.png`

参考图中的 42% 透明度标注不作为实现数值，实际使用约 58%。参考图顶部的“制作档案”“复盘手记”“关于项目”等栏目仅作为排版风格参考，不照搬其信息结构。成片播放结束前不提供通往两个深入内容的入口；片头顶栏只保留项目标识和必要的影片播放控制。

片头中央提供“观看完整成片”按钮。片头不提前显示“复盘手记”和“提示词和图片”两个主要选择。

### 4.2 完整成片

点击播放按钮后，进入沉浸式播放器：

- 正常速度播放。
- 正常亮度显示。
- 开启影片声音。
- 支持播放、暂停、音量、进度、全屏和退出。
- 使用经过网页优化的视频版本，原始 370 MB 文件保持不动。

原始成片来源：

- `D:\chenx\Videos\初恋旧爱新欢.mp4`

### 4.3 播放结束

成片结束后：

1. 最后一帧停留约 1 秒。
2. 画面逐渐变暗，但保留最后一帧作为背景。
3. 文案淡入：“如果你愿意，可以继续看看这部作品是怎样完成的。”
4. 显示两个并列入口：“复盘手记”和“提示词和图片”。
5. 提供较弱的“重新观看影片”按钮。

电脑端两个入口左右排列，手机端上下排列。

## 5. 复盘手记

### 5.1 目录

复盘手记首先显示封面和五个主要章节：

1. 项目缘起：我为什么要做这个视频
2. 故事设计：一个想法怎么变成完整叙事
3. 制作执行：生图、视频与剪辑
4. 回看成片：我看到的不足
5. 写在最后：关于经历、创作方式与这份复盘

每章显示标题、简短摘要、预计阅读时间和代表图片。点击章节后进入阅读模式。

### 5.2 阅读模式

两万字正文拆成约 20–30 个阅读页面，每页约 600–1000 字，以完整观点或完整案例为分页边界，不做机械截断。

阅读页包含：

- 当前章节、小节和整体页码。
- 可收起的小节目录。
- 上一页、下一页和返回目录。
- 自动记录上次阅读位置。
- 51 处正文案例媒体（25 张图片、26 段视频）严格保留在原 Markdown 的出现位置和顺序；图片支持点击放大，视频原位播放。
- 重复出现的媒体按原文重复展示，不因底层文件相同而合并或移动。
- 图片较多的案例可单独占一个图像页。
- 具体案例可链接到“提示词和图片”中的对应案例。
- 返回片后选择的固定入口。

视觉使用低饱和暖灰和略亮的纸张色阅读区域。标题可以延续古典电影气质，正文优先保证清晰和长时间阅读舒适度。

## 6. 提示词和图片

### 6.1 内容组织

原始 Canvas 包含 72 个文本节点、139 次图片引用和 137 张不同图片。网站以“制作案例”为基本单位，不把图片与提示词拆散。

一个案例可以包含：

- 单张生图及提示词。
- 首帧与尾帧及视频提示词。
- 多张候选图及共同提示词。
- 转场、动作或声音说明。

### 6.2 案例总览

总览页显示全部约 72 个案例，提供：

- 搜索：同时匹配场景名和完整提示词。
- 筛选：全部、生图、图生视频、首尾帧、转场、剪辑参考。
- 情节标签：教室、商场、婚礼、病房、雨夜小区等。
- 案例卡片：代表图片或首尾帧、场景名、提示词类型、图片数量和情节标签。

筛选只改变当前显示内容，不删除或永久隐藏任何案例。

### 6.3 案例详情

点击案例后显示：

- 图片展示区和候选图切换。
- 首帧、尾帧明确标识。
- 完整提示词，不截断。
- 一键复制提示词。
- 上一个案例、下一个案例和返回全部案例。
- 链接到复盘手记中讨论该案例的段落。
- 返回片后选择。

图片支持放大查看。案例顺序优先按照影片情节和制作流程整理。

- 当前项目中的 `canvas-data.json`

## 7. 内容与数据边界

网站由三个独立内容模块组成：

1. `film`：片头背景和完整成片播放器。
2. `review`：章节、阅读页、图片引用和阅读进度。
3. `archive`：案例、图片组、提示词、类型和标签。

页面只读取经过整理的本地网站数据，不在浏览器中直接解析 Obsidian 文件。构建脚本负责把 Markdown 和 Canvas 转换为稳定的 JSON 数据，并检查图片是否存在。

模块之间通过稳定标识互相链接：复盘段落可以指向案例，案例也可以返回对应复盘段落。未建立对应关系的内容仍可独立浏览，不显示错误链接。

## 8. 异常与降级

- 浏览器禁止自动播放时，片头显示视频第一帧和明确的播放按钮。
- 手机或低性能设备无法流畅播放 4 倍速背景时，使用较短的网页优化循环片段，但视觉上仍保持全屏动态背景。
- 完整成片加载失败时显示重试和返回片头，不自动跳过。
- 图片缺失时显示案例名称和缺失提示，不让页面布局崩坏。
- 复制提示词失败时选中文字并提示访客手动复制。
- 阅读进度无法保存时仍可正常翻页，不阻止阅读。
- 搜索没有结果时显示清晰的空状态和“清除筛选”。

## 9. 响应式设计

- 桌面端片头文字保持完整居中构图。
- 手机端在不改变文字设计核心层级的前提下缩小字号和间距。
- 片后两个入口在手机端改为上下排列。
- 复盘小节目录在手机端收进可展开菜单。
- 案例详情在桌面端图片与提示词并排，在手机端改为图片在上、提示词在下。

## 10. 验证要求

### 内容验证

- 复盘正文无缺章、无乱码。
- 137 张不同图片全部能被访问。
- 每个案例的图片和提示词映射正确。
- 首帧和尾帧顺序正确。
- 内部交叉链接不存在无效目标。

### 功能验证

- 片头背景能播放、循环、静音并使用目标倍速。
- 完整成片以正常速度和声音播放。
- 播放结束后可靠进入片后选择。
- 两个入口、返回、上一页、下一页和搜索筛选均可用。
- 提示词复制和阅读进度记录有效。

### 视觉验证

- 桌面和手机均进行截图检查。
- 使用成片中的明亮、中间和黑暗镜头检查文字对比度。
- 首页实现结果与 `design-references/homepage-approved.png` 对比。
- 不允许出现溢出、遮挡、图片拉伸或正文行宽过长。

### 性能验证

- 不直接把 370 MB 原片作为自动播放背景。
- 背景视频与完整成片分别生成网页优化版本。
- 图片使用适合页面尺寸的版本，并保留点击查看大图能力。
- 案例总览采用延迟加载，避免首次载入全部大图。

## 11. 最终页面关系

```text
片头 / 高倍速半透明背景视频
└── 完整成片播放器
    └── 片后选择
        ├── 复盘手记目录
        │   └── 分页阅读
        └── 提示词和图片总览
            └── 案例详情
```

这是当前项目的完整范围。任何新增栏目、登录、评论、后台编辑、公开投稿或社交功能均不在本轮实现范围内。
