# 分区完整加载与无空卡媒体方案

## 背景

网站当前公开资源约 510 MB，其中：

- 隧道图片 137 张，约 269 MB；
- 复盘图片约 51.6 MB；
- 复盘视频约 81.5 MB；
- 首页与完整影片约 77.7 MB；
- 音频约 12.3 MB。

上一轮将媒体改为进入页面后再请求，虽然首页更早出现，但隧道会在图片尚未下载时先显示大量空卡，违背沉浸式浏览的目标。该版本先回退到此前的资源预热行为，再基于恢复后的版本实施本方案。

## 目标

1. 用户进入隧道后，137 张卡片必须全部已经具备可显示图片，不能出现空白、零散补图或边走边加载。
2. 不要求首次打开网站时下载完整的 510 MB；资源按照功能分区准备。
3. 隧道展示图显著减小体积，但点击卡片后的详情仍使用原始高清图片。
4. 不改变任何图片顺序、案例归属、提示词、错误案例分支、首尾帧关系或复盘媒体位置。
5. 复盘翻页时，目标页媒体准备好以后再完成翻页，避免翻到空白媒体框。

## 采用方案

### 1. 恢复稳定基线

先撤销上一轮渐进式媒体改动，恢复此前公开版本的：

- 首屏资源预热流程；
- 首页背景影片表现；
- BGM 初始化行为；
- 原有隧道、思维导图、复盘阅读和交互动效。

回退使用新的 Git 提交完成，不重写历史。

### 2. 隧道专用展示图

为 `assets/canvas-images` 中的 137 张原图生成独立的网页展示版本：

- 输出到新的专用目录，不覆盖原图；
- 使用 WebP；
- 保持原始宽高比；
- 长边最大 1280 像素；
- 默认编码质量为 86，并固定编码器版本以保证输出可重复；
- 文件名和 137 个出现顺序保持一一对应；
- 构建时记录源文件与展示文件的映射、尺寸和字节数。

隧道卡片只使用展示图。详情弹窗、首尾帧上下展示和需要放大阅读的地方继续使用原始高清文件。

展示图总量的目标上限为 50 MB。若首次生成结果超过 50 MB，统一编码质量以 2 为步长下调，但不得低于 80，也不降低 1280 像素的尺寸上限；任何单张图如果出现明显色块、文字不可读或水彩纹理破坏，则对该图使用更高质量参数单独生成并记录例外。若质量 80 时仍超过 50 MB，则停止构建并重新评估，而不是继续牺牲画质。

### 3. 进入隧道前完整准备

用户点击进入“提示词和图片”后：

1. 先读取档案数据；
2. 显示与网站风格一致的分区加载过渡；
3. 以有限并发下载 137 张隧道展示图；
4. 每张图片必须完成浏览器解码；
5. 全部 137 张成功后才挂载并显示隧道画布；
6. 隧道出现时所有卡片一次性完整可见。

加载进度使用真实完成数量，例如 `84 / 137`，不能使用假进度或纯计时动画。

### 4. 错误与重试

- 单张展示图失败后自动重试两次；
- 仍失败时不进入隧道，保留加载过渡并明确显示失败数量；
- 提供“重新加载”和“返回选择”；
- 重试只请求失败项，不重新下载已成功并解码的图片；
- 用户离开路由时终止未完成请求和界面更新。

不设置“跳过并进入”按钮，因为该按钮会重新制造空卡体验。

### 5. 复盘页面媒体准备

翻向下一页或上一页时：

- 先读取目标页数据；
- 图片必须下载并解码；
- 视频至少达到可展示封面和可开始播放的状态；
- 媒体准备期间保留当前页，并显示轻量翻页等待反馈；
- 目标页准备完成后再执行真实翻页动画。

只准备即将进入的页面，并在空闲时预热相邻一页，不能同时下载全部复盘视频。

### 6. 缓存

同一次访问中维护已完成资源集合：

- 从隧道返回再进入时，不重复解码已经成功的展示图；
- 复盘相邻页返回时复用已准备资源；
- 新部署仍以文件名或版本映射区分资源，避免旧缓存与新内容混用。

本阶段不增加 Service Worker，避免引入部署后旧版本长期缓存的问题。

## 用户界面

分区加载过渡覆盖档案画布区域，但保留网站整体背景和返回入口。视觉沿用现有暗色电影档案风格，不新做一套突兀的加载页。

隧道加载完成后的第一帧必须是完整构图，不允许先显示结构、随后零散补图。进入动画只负责视觉过渡，不承担掩盖资源加载的作用。

## 构建与数据

- 原始图片继续作为权威来源；
- 构建脚本生成展示图和映射数据；
- 构建必须可重复执行；
- 未改变的源文件应产生稳定输出；
- 缺失、重复或无法映射的源文件必须使构建失败；
- 不允许人工移动案例或根据文件名猜测顺序，顺序继续来自现有档案数据。

## 验收标准

1. 模拟较慢网络，从选择页进入隧道时先看到真实进度。
2. 隧道 DOM 出现时，137 张展示图均已完成解码，`naturalWidth > 0`。
3. 隧道首次完整显示后不存在空卡、透明卡或加载中占位卡。
4. 隧道展示资源合计不超过 50 MB。
5. 点击任意卡片后，详情仍显示对应原始高清图；首尾帧仍上下排列。
6. 137 张图片的顺序、重复出现、错误案例标记和案例归属与当前档案数据完全一致。
7. 复盘翻页不会先显示空白图片或未准备的视频框。
8. 现有鼠标圆环、粒子互动、思维导图拖动、隧道拖动与回溯、真实翻页效果不退化。
9. 所有自动测试通过，并在正式 GitHub Pages 地址上完成慢网浏览器验收。

## 非目标

- 不压缩或替换原始高清档案；
- 不重新设计隧道构图；
- 不改变网站内容、分类或案例顺序；
- 不要求首次访问时完整下载全部 510 MB；
- 不在本阶段迁移新的付费存储或 CDN。
