# 路线加载界面动态设计

## 已选方向

采用第一组加载动画 Demo B「文字苏醒」，同时用于“提示词与图片”和“复盘手记”两条内容路线。两条路线共享构图、动效节奏和交互语言，但使用各自的真实资源数量与文字。

## 视觉结构

- 加载界面覆盖整个视口，不提前露出尚未准备好的正文、图片或隧道卡片。
- 背景为深黑色空间和极淡的坐标网格；鼠标附近出现低亮度暖色光影。
- 中央使用四个大号中文字符，字符从下向上逐字显现。
- 提示词路线显示“画面就绪”，复盘路线显示“手记就绪”。
- 大字下方不放“所有资源准备完成后……”等解释性小字。
- 大字下只保留真实数量、线性进度和四个简短准备阶段。
- 不使用圆形旋转器、旋转条纹或循环转圈图标。

## 提示词与图片路线

- 英文标识：`PROMPT & IMAGE ARCHIVE`
- 大字：`画面就绪`
- 真实进度格式：`000 / 137`
- 阶段：`读取目录`、`下载素材`、`解码画面`、`准备进入`
- 数量只在一张隧道展示图完成下载并解码后增加。

## 复盘手记路线

- 英文标识：`THE MAKING-OF NOTES`
- 大字：`手记就绪`
- 总数按首次进入手记需要准备的实际项目计算，不使用 Demo 中的固定数字。
- 进度项目包括正文数据、当前双页图片解码、视频元数据和互动导图模型。
- 阶段仍使用四段式表达，但根据实际准备流程点亮。

## 完成与失败状态

- 全部项目准备完成后，四个大字全部点亮，进度线抵达终点。
- 完成状态停留不超过一秒：
  - 提示词：`全部画面已准备完成`
  - 复盘：`复盘手记已准备完成`
- 完成后自动进入目标内容，不要求用户再次点击。
- 任意必须资源在自动重试后仍失败时，不进入内容页。
- 失败提示放在进度区域，不重新加入大字下方的常驻说明文案。
- 提供“重新加载失败项目”按钮，只重试失败资源。

## 动效与可访问性

- 大字显现顺序由真实总体进度驱动，不使用与加载无关的固定倒计时。
- 真实数量和线性进度条始终同步。
- 四个阶段随真实任务状态点亮。
- 鼠标只影响背景光影和网格可见度，不影响按钮点击及进度。
- 用户启用“减少动态效果”时，字符直接切换显示状态并关闭鼠标光影。
- 加载状态使用 `aria-live`，不能只靠颜色或动画表达。

## 验收

1. 两条路线都使用 B 方案，但大字、资源总数和阶段状态各自正确。
2. 大字下没有解释性小字。
3. 内容页不会在必需资源准备完成前出现。
4. 加载界面没有圆形旋转器和旋转条纹。
5. 失败后仍停留在加载界面，可以只重试失败资源。
6. 鼠标互动和减少动态效果设置均正常。
